# `a2a-mailbox` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `a2a-mailbox` (`v0.1.0`), an executor-less A2A inbox server and `a2a` command plugin (`a2a mailbox`) that registers incoming A2A requests into a local DB, `tk` ticket repository, or Cloud Pub/Sub topic, and works simultaneously alongside `a2a-select`.

**Architecture:** Modular Go CLI (`go 1.25+`, standard library only) with three packages: `internal/store` (`DBBackend`, `TKBackend`, `PubSubBackend`), `internal/server` (A2A v1.0 HTTP+JSON server), and `internal/cli` (subcommands `serve`, `list`, `show`, `reply`, `info`), plus an end-to-end `evals/` test suite.

**Tech Stack:** Go (`net/http`, `encoding/json`, `encoding/base64`, `os/exec`, `flag`, `testing`).

**Spec:** `docs/superpowers/specs/2026-10-17-a2a-mailbox-design.md`

## Verification Plan

### Automated Security Check
- **Security Scanner**: Check for SecureCoder scanner API port and scan all newly created files if active.
- **Security Audit**: Enforce `mandatory-secure-web-skills`:
  - System Command Execution: Validate `tk` binary path via `exec.LookPath` and pass discrete argument slices to `exec.CommandContext` without shell interpolation.
  - Path & File System Security: Clean and validate all file paths; enforce `0o600` on DB files and `0o700` on directories.
  - Testing & Server Binding: Bind all test and default servers strictly to `127.0.0.1` (`localhost`), never `0.0.0.0`.
  - Document findings in `walkthrough.md`.
